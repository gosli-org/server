For a brief repo description, read [README.md](README.md).

When using or changing project terminology, read [GLOSSARY.md](GLOSSARY.md), use its defined terms, and respect its explicitly avoided synonyms.

Before designing, implementing, testing, or reviewing server behavior, read [docs/behavior.md](docs/behavior.md) for expected behavior and unresolved questions.

Before working on server internals, read [ARCHITECTURE.md](ARCHITECTURE.md) for internal structure and technical constraints.

Before proposing or changing an architectural decision, read relevant ADRs in `docs/adr/`, if present and not already available in the current context. If the proposal contradicts an existing ADR, identify it explicitly and explain why the decision should be reconsidered.

Before creating a branch or preparing changes for review, read [CONTRIBUTING.md](CONTRIBUTING.md).

Before tracker operations, read [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

Before triaging, also read [docs/agents/triage-labels.md](docs/agents/triage-labels.md).
